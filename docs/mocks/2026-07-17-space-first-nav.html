Space-first navigation

Spaces become the top-most context. Each space holds three modes — Agent (configure the space, draft notes, manage phrases by talking to it), Talk (existing), and Notes (existing). Three shell alternatives below; mode tabs in each frame are clickable. Composer keeps its structure, restyled.

Companion doc with tradeoffs, gaps & open questions: docs/plans/2026-07-17-space-first-nav.md

ASpace rail — spaces live in the sidebar

The indigo sidebar lists spaces directly; the hierarchy is visible in the shell. Modes are a segmented control in the header. Bottom space tabs are gone. Scales to many spaces, but on iPad (rail-collapsed) switching costs two interactions.

Leaning: B as the base, borrowing C's handoff rule

Keystroke economy is the design thesis, and the bottom dock is the cheapest space switch — one tap, adjacent to where attention already lives. Grow the header toggle to Agent | Talk | Notes. Adopt A's sidebar space list later only if docks outgrow ~6 spaces (dock = pinned/recent, sidebar = all). From C, keep the hard rule everywhere: agent output is never directly speakable — it hands off explicitly ("Save as phrase" · "Open in Notes" · "Insert into composer"), and the agent surface never shows the indigo Speak button.
