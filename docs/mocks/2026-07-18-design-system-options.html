Design system options — typography, radius, spacing

Three token systems applied to the same two surfaces from today's app (Talk and Notes). All three keep the locked DESIGN.md decisions: Noto Sans only, zinc + indigo, solid indigo rail, roomy AAC-first density, ≥44px targets. They differ in radius roles, type scale, and rhythm.

Why — current drift (from code audit, 2026-07-18)

  • 14 distinct radius utilities in app code: rounded-lg ×78, rounded-full ×76, rounded-md ×60, rounded-xl ×21, plus rounded-2xl, rounded-sm, rounded-xs, bare rounded…
  • Same-role elements disagree: word tokens rounded-lg · composer rounded-2xl · cards rounded-xl · dock tabs rounded-full · enter key rounded-lg · buttons rounded-md.
  • Type has arbitrary values (text-[15px], text-[11px]) and a big unexplained jump: composer text-2xl vs tokens text-base vs UI text-sm.
  • DESIGN.md's radius role table (buttons md, cards xl) no longer matches what the code does.

Recommendation

Option B (Soft Companion) fits the thesis best — “calm, dignified, low-effort” reads rounder and bigger, not crisper. The full-radius primaries make the two actions that matter (Speak, dock tabs) unmistakable, and the 15px body / 18px token bump helps the audience most. It's also the closest to what the newest surfaces (composer, dock) already do, so churn concentrates in older screens.

Option A is the safe codify-what-exists pass (least churn, no visual opinion). Option C is the most "designed" but its squarer chrome fights the friendly dock/composer you just shipped. Whichever wins: the token roles (control / chip / surface / primary-pill) go into globals.css as CSS vars + DESIGN.md, and the 14 ad-hoc radii collapse to 4.
