Voice — one page for choosing & cloning

Today voice is split across three routes: Settings → Voice (pick the voice that speaks for you), /clone (record/upload samples to build a custom voice), and /voices (find ElevenLabs library voices similar to your samples). This mock proposes folding all of it into a single Voice page and shows three ways to do it.

Why combine

A cloned voice is just a voice you can select — it should live in the same list as everything else and become the active voice the moment it's made. Splitting "make a voice" from "choose a voice" forces the user to cross routes to finish one intention: "I want this to sound like me." The similar-voices matcher is really a discovery aid for cloning, so it belongs beside it, not on its own page.

Shared anatomy across all three options: a current-voice banner at top (who speaks + preview), one voice list that includes cloned voices badged Cloned, a create-voice affordance, and fine-tune controls (speed + provider-specific sliders) tucked into a disclosure so the page stays calm.

Recommendation → Option A. Cloning is occasional and multi-step; selection is the everyday task. Keep the page about selection and open cloning in a focused drawer, so the common path stays a single quiet list and the rare path gets room without crowding it.
Option A

Selection is the page · cloning is a drawer

The page is the voice list, with the active voice pinned on top and a "Clone your voice" row seated at the head of your voices. Clicking it slides in a focused drawer with the record/upload → name → create wizard; the finished clone drops into the list already selected. Everyday selection stays one uncluttered surface.

Cloned voices sit at the top; the library follows. "Clone a voice" opens the wizard in a right-hand drawer (shown in Option B/C flows).

Strengths

  • Everyday task (pick a voice) stays a single calm list — on-thesis.
  • Multi-step cloning gets a focused surface without pushing tuning/list off-screen.
  • Cloned voice appears selected in-list the instant it's created — one clear result.
  • Smallest change to today's components: reuse VoicesList + move the clone form into a Sheet.

Costs

  • Cloning lives behind a click — slightly less discoverable than fully inline.
  • Drawer over a data-heavy page needs care on tablet portrait / mobile (becomes full-screen sheet).
Option B

One page, two segments · Choose / Create

Active-voice banner on top, then a segmented control: Choose a voice (the searchable list, cloned + library) and Create a voice (the clone wizard, inline). Both modes share the route and the banner, so the create flow never leaves the page. Similar-voice matching folds in as a helper inside Create.

Strengths

  • Both intents are visible and named on the same surface — nothing hidden.
  • Create flow has full page width; no cramped drawer on small screens.
  • Segmented control reads as a clean either/or, matches the dock/tab idiom already in the app.

Costs

  • Two modes on one route = more state; back/deep-link behavior needs a URL param.
  • Tuning controls only make sense in Choose mode — the page's shape shifts between segments.
  • Slightly heavier than A for what is, most days, just "pick a voice."
Option C

One scroll · everything inline, progressively disclosed

No modes, no drawer — a single scroll. Active voice, then the list, then a persistent "Clone your voice" panel that expands in place into the record → name → create wizard, then fine-tuning. Most transparent; longest page. Good when cloning is a first-class, expected step rather than an occasional one.

Strengths

  • Zero navigation — the whole voice story is one scroll, fully transparent.
  • Cloning reads as a normal, expected step, not a hidden power feature.
  • "Find similar" naturally nests as an alternative to cloning, retiring the orphan /voices page.

Costs

  • Longest, densest page — competes with the "calm, roomy" thesis if always expanded.
  • Recording UI + list + tuning on one scroll is a lot for switch/gaze users to traverse.
  • Most build effort; wizard state lives inline in the route.

Cross-cutting decisions (apply to whichever we pick)

  • Sidebar: the "Voice" item points here (replaces its current /clone target). One destination for everything voice.
  • Settings → Voice: either redirects here or shrinks to a link ("Manage voices →"), so there's a single source of truth.
  • /clone and /voices: retired as standalone routes; /voices's similar-match becomes a helper inside the clone flow.
  • Provider & API key: keep the "Powered by" provider line and the ElevenLabs-key warning from today's voice form; cloning stays ElevenLabs-gated with the same callout.
  • Result of a clone: new voice is auto-selected and shown in the "Your voices" group — the create flow ends where selection begins.
