Why this one

  • Zero clicks in the normal path. Both answers are already correct, so the user presses Continue.
  • The user reads a job ("Voice"), not a brand they do not know.
  • Two services that do the same job cannot both look active. The radio makes the choice explicit.
  • It reuses the two-column Field from the profile step. No new layout.

What it costs

  • A service that does two jobs must appear twice. Gemini does text and voice, so plan for that.
  • The key field is inside a choice card, so the card grows tall when it is selected.

Where it wins

  • The fewest keystrokes of the three, which is the product thesis.
  • It is honest. On a Mac with Apple Intelligence there is truly nothing to do.
  • It removes a step from onboarding instead of adding one.

Where it fails

  • The Mac without Apple Intelligence sees two empty ticks, and the screen becomes a lie.
  • A caregiver with an ElevenLabs key must find Settings during the one moment they are sitting there.
  • The "Choose setup" step promises key entry today. That promise breaks.

QuestionAnswer
Where do keys live?The macOS Keychain, through a Rust command. Not in SQLite, and not in the React draft. The UI holds a status, never the key.
When is a key tested?On Connect, and again at app start. A key that works in June can fail in August, so the status must refresh.
What if a check fails?Fall back to the free service, show the badge, and continue. A broken key must never block speech.
Which calls does the UI make?None. The React code invokes Rust commands. Rust holds the key and speaks to the network.

Recommendation

Build Option A for onboarding. Build Option B for Settings. They share the service data, not the layout.

Option A asks the two questions the user can answer, and it pre-answers both. Option B is the correct shape for Settings, where the user comes back later to fix a key. Option C is the fastest to build, but it breaks on a Mac that has no Apple Intelligence, and that is a large part of the audience.

One problem to correct first. The "Choose setup" step says free mode sends your message to OpenRouter. On a Mac with Apple Intelligence that is wrong, and it is worse than the truth. Free mode must read: writing help runs on this Mac, and nothing leaves it. This makes free mode the private option, and it removes the reason most users had to open the Connect step at all.

  1. Correct the free-mode copy in SETUP_MODES, with an Apple Intelligence check behind it.
  2. Add the /connect step and the branch in canReach().
  3. Add the Rust commands for the Keychain and the key tests.
  4. Build the Option A step, then reuse the same data in Settings with the Option B card.
